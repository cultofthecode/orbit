# AGENTS.md — internal/orbstack

The adapter to OrbStack, through the `orb` CLI. It is the only package with OrbStack-specific code (R07). Read the root `AGENTS.md` and `ARCHITECTURE.md` (Provisioning requirements) first. Every change here is `risk-high`.

## Layout

- `orbstack.go` — `Client`: `Create`, `Exists`, `Mounts`, `State`, `Start`, `Stop`, `ActiveMounts`, `Delete`, `RunAsRoot`, `RunAsAgent`; the constant `AgentUser`. Each argument list of `orb`, and each parser of its output, is a small pure function with a unit test.
- `orbstacktest/` — the in-memory fake for handler tests. It imports nothing from the adapter.
- `integration_test.go` — tests against a real OrbStack, behind the `integration` build tag.

## Invariants

- `createArgs` always passes `--isolated`, `--isolate-network`, and one mount in the form `DIR:DIR`. A caller cannot change them. A mount without a destination lands under `/mnt/mac`.
- `Create` refuses a directory that is not absolute or that holds a colon or a comma (`ErrMountPath`). `orb` splits a mount at the first colon, so such a path mounts another directory than the one that was validated; OrbStack stores the mounts of a machine as a list with commas.
- `Mounts` reads the configured mounts of every machine from `orb list --format json`. `ActiveMounts` reads `/proc/self/mountinfo` as root in the machine and returns the mounts of the file system `virtiofs` with the source `mac`: its root is the root of the host, so the root of each mount is the host path of the mounted directory as the machine resolved it. It shows a symlink that was swapped in before the mount was made. It does not show a path that was removed and recreated as a symlink between two starts: after a restart it still reports the stored path while the machine serves the target (OrbStack 2.2.5). It is not proof of the identity of the mounted directory. Both fail with `ErrMountTable` on output they cannot read and on a mount point that appears twice; they never guess.
- `Create`, `State`, `Start`, `Stop`, `ActiveMounts`, `Delete`, `RunAsRoot`, and `RunAsAgent` refuse a name without the prefix of the client (`ErrForeignMachine`) before they run a command.
- Never run `orb stop` or `orb start` without a machine name. `orb stop` with no machine stops OrbStack with every machine, and `orb start` with no machine starts every machine that ran when OrbStack last stopped. `startArgs` and `stopArgs` are exactly `start NAME` and `stop NAME`; `Start` and `Stop` refuse a name without the prefix (`ErrForeignMachine`) and a name with white space (`ErrMachineName`) before any command, also before `orb status`.
- `State` reads the `state` field of `orb list --format json` and returns `""` for no machine. It runs only `orb status` and `orb list`, so it never starts a machine. It fails with `ErrMachineList` on output it cannot read, on a name listed twice, and on an entry without a state; it never guesses. Every `-m` command (`ActiveMounts`, `RunAsRoot`, `RunAsAgent`) starts a stopped machine, so a slice reads `State` first and runs them only on a `running` machine.
- `RunAsRoot` runs `orb -m NAME -u root bash -s` with the script on standard input. The user is fixed; no argument of the caller reaches the command line. `RunAsAgent` runs `orb -m NAME -u agent bash -s` the same way: its user is the constant `AgentUser`, never an argument, and no argument of the caller reaches the command line. A test in `cmd/orbit` checks that `AgentUser` equals `provision.AgentUser`. A client with an empty prefix refuses every name. `cmd/orbit` passes `sandbox.NamePrefix`.
- The adapter imports no other package of this repository. Only `cmd/orbit` imports the adapter; `golangci-lint` (depguard) fails on any other import. Slices use `orbstacktest` in tests.
- The adapter does not pass `--forward-ssh-agent`. Add an operation only when a slice needs it, and add it to the fake in the same change.
- Every command of `orb` runs through `execute`, which gives `orb` the environment of the process without the variables in `strippedVariables`, matched by exact name: `ORBENV`, `WSLENV`, `HTTP_PROXY`, `HTTPS_PROXY`, `ALL_PROXY`, `FTP_PROXY`, `http_proxy`, `https_proxy`, `all_proxy`, `ftp_proxy`, and `ELECTRON_RUN_AS_NODE`; and without every variable whose name starts with `strippedPrefix`, `DOCKER_` in uppercase (`DOCKER_HOST`, `DOCKER_AUTH_CONFIG`, `DOCKER_CONFIG`, `DOCKER_CONTEXT`, any `DOCKER_X`). `orb` copies each of them into the command that it runs in the machine, as root and as the agent, and `ORBENV` and `WSLENV` also copy every host variable that they name (OrbStack 2.2.5). A proxy URL or `DOCKER_AUTH_CONFIG` can hold a credential, so without the removal a host credential could enter a sandbox without an opt-in (R08), and `DOCKER_HOST` points the Docker client in the machine at an endpoint of the host. Names that differ only in letter case (`docker_host`, `Http_Proxy`) stay: `orb` does not forward them. `orb` still copies the other variables that it forwards by itself: terminal values (`TERM`, `TERM_PROGRAM`, `TERM_PROGRAM_VERSION`, `COLORTERM`, `ITERM_*`, `WEZTERM_*`), locale values (`LANG`, `LC_*`), `__CF*` values, and `COMMAND_MODE`. Keep the rest of the environment: `orb` finds OrbStack through `HOME`. Do not run `orb` outside `execute`, and add a variable to `strippedVariables` when a version of OrbStack forwards a credential or an endpoint through another one.
- The client never starts OrbStack. `orb` starts a stopped OrbStack by itself on any command that needs it (OrbStack 2.2.5, #62), so every command of the client first runs `orb status`, which only reports the state. Unless it prints `Running` and exits 0, the client runs no other command and fails: with `ErrNotRunning` and the advice to start OrbStack for `Stopped` or `Starting`, with an error for any other output. Do not add a path to `orb` that skips this check.
- `orb` finds OrbStack through `$HOME/.orbstack`. Under another `HOME` it prints `Stopped` while OrbStack runs (#70). Before `orb status` runs, the client reads `HOME`, the home directory of the account from the user database (`user.Current`), and whether `$HOME/.orbstack` is a directory. When `orb status` prints `Stopped` or `Starting` and `HOME` is not absolute, is not the same directory as the account home (symlinks resolved, then `os.SameFile`), or has no `.orbstack` directory, the client fails with `ErrHome`, which names `HOME` as the cause and advice for that cause, not with `ErrNotRunning`. It runs no other command. The client never runs `orb` with another `HOME` (owner decision on #70); `execute` only removes the variables listed above.
- An error of a failed command wraps the error of `os/exec` and carries the standard error of `orb`, when `orb` printed anything.
- The fake applies the same prefix rule, the same white-space rule for `Start` and `Stop`, and the same mount-path rule as the adapter, with sentinel errors of its own. Keep the two in step. It keeps a state per machine that `Create`, `Start`, and `Stop` change; its `ActiveMounts`, `RunAsRoot`, and `RunAsAgent` fail with `ErrStopped` for a machine that exists and is not running, so that a handler test catches an implicit start.

## Validation

- `go test ./internal/orbstack/...` needs no OrbStack.
- `go test -tags integration -count=1 -v ./internal/orbstack/...` needs a running OrbStack. It creates one machine named `orbit-it-<random>` and deletes it; it registers the deletion only after it saw that no machine has that name. Never touch a machine whose name does not start with `orbit-it-` from a test.
