# AGENTS.md — internal/orbstack

The adapter to OrbStack, through the `orb` CLI. It is the only package with OrbStack-specific code (R07). Read the root `AGENTS.md` and `ARCHITECTURE.md` (Provisioning requirements) first. Every change here is `risk-high`.

## Layout

- `orbstack.go` — `Client`: `Create`, `Exists`, `Mounts`, `List`, `State`, `Start`, `Stop`, `ActiveMounts`, `Delete`, `RunAsRoot`, `RunAsAgent`, `Shell`; the constant `AgentUser`. Each argument list of `orb`, and each parser of its output, is a small pure function with a unit test.
- `orbstacktest/` — the in-memory fake for handler tests. It imports nothing from the adapter.
- `integration_test.go` — tests against a real OrbStack, behind the `integration` build tag.

## Invariants

- `List` is read-only: it runs only `orb status` and one `orb list --format json`, never a `-m` command, and returns only machines whose names start with the prefix of the client (never the bare prefix). Output that is not a JSON array (empty output included) and a prefixed name that is listed twice fail with `ErrMachineList`; `[]` (what OrbStack prints with no machine) and `null` are no machines. It is never retried. `orbstacktest.Fake.List` returns its own `orbstacktest.Machine`, because the fake imports nothing from the adapter.

- The image table (`pins`) is the only place that names an OrbStack image (R07). `Create(ctx, name, dir, key, forward)` takes a distribution key (`Distributions()`: `ubuntu`, `debian`), never an image; `createArgs` looks it up exactly and fails with `ErrDistribution` for anything else (an image, a version, an empty string, white space, a leading `-`), before any command. Pins are `ubuntu:26.04` and `debian:trixie`, never a bare name; a pin changes only in a change that runs the integration tests (`TestCreateUsesThePinnedImageOfEveryDistribution`) and the escape suite on it. `cmd/orbit` tests that the keys equal `sandbox.Distributions()`.
- `createArgs` always passes `--isolated`, `--isolate-network`, and one mount in the form `DIR:DIR`. A caller cannot change them. A mount without a destination lands under `/mnt/mac`.
- `Create` refuses a directory that is not absolute or that holds a colon or a comma (`ErrMountPath`). `orb` splits a mount at the first colon, so such a path mounts another directory than the one that was validated; OrbStack stores the mounts of a machine as a list with commas.
- `Mounts` reads the configured mounts of every machine from `orb list --format json`. `ActiveMounts` reads `/proc/self/mountinfo` as root in the machine and returns the mounts of the file system `virtiofs` with the source `mac`: its root is the root of the host, so the root of each mount is the host path of the mounted directory as the machine resolved it. It shows a symlink that was swapped in before the mount was made. It does not show a path that was removed and recreated as a symlink between two starts: after a restart it still reports the stored path while the machine serves the target (OrbStack 2.2.5). It is not proof of the identity of the mounted directory. Both fail with `ErrMountTable` on output they cannot read and on a mount point that appears twice; they never guess. Empty output of `cat /proc/self/mountinfo` (exit 0, nothing printed; seen once under load, #82) fails with `ErrMountTable` and the message "the mount table is empty", because a real table always lists `/`; `ActiveMounts` does not retry an empty read (owner decision, 2026-11-12, #82); it fails closed and never returns an empty map.
- The client never starts a machine: only `Start` runs `orb start`, and `orbit start` is the only slice that calls it, after its own nesting refusal. Do not add a path to `orb -m` that skips `checkRunningMachine`. `TestMachineCommandsRunOnlyInARunningMachine` and the integration test `TestNoMachineCommandStartsAStoppedMachine` check it for every such method.
- `Create`, `State`, `Start`, `Stop`, `ActiveMounts`, `Delete`, `RunAsRoot`, `RunAsAgent`, and `Shell` refuse a name without the prefix of the client (`ErrForeignMachine`) before they run a command.
- Never run `orb stop` or `orb start` without a machine name. `orb stop` with no machine stops OrbStack with every machine, and `orb start` with no machine starts every machine that ran when OrbStack last stopped. `startArgs` and `stopArgs` are exactly `start NAME` and `stop NAME`; `Start` and `Stop` refuse a name without the prefix (`ErrForeignMachine`) and a name with white space (`ErrMachineName`) before any command, also before `orb status`.
- `State` reads the `state` field of `orb list --format json` and returns `""` for no machine. It runs only `orb status` and `orb list`, so it never starts a machine. It fails with `ErrMachineList` on output it cannot read, on a name listed twice, and on an entry without a state; it never guesses. Every `-m` command (`ActiveMounts`, `RunAsRoot`, `RunAsAgent`, `Shell`) starts a stopped machine (OrbStack 2.2.5, #75), so each of them reads `State` itself (`checkRunningMachine`) after the prefix check and runs `orb -m` only on a `running` machine; for any other state, and for a machine that is not listed, it fails with `ErrMachineNotRunning` and runs nothing else than `orb status` and `orb list`. A slice still reads `State` first, to give its own advice (`orbit start`). The machine can stop between the check and the `orb -m` command that follows; the owner accepted that window, as for OrbStack in #62 (decision on #75, 2026-11-12), because `orb` has no flag that prevents a start; the herdr spike measures it later.
- `RunAsRoot` runs `orb -m NAME -u root bash -s` with the script on standard input. The user is fixed; no argument of the caller reaches the command line. `RunAsAgent` runs `orb -m NAME -u agent bash -s` the same way: its user is the constant `AgentUser`, never an argument, and no argument of the caller reaches the command line. A test in `cmd/orbit` checks that `AgentUser` equals `provision.AgentUser`. A client with an empty prefix refuses every name. `cmd/orbit` passes `sandbox.NamePrefix`.
- `Shell` runs `orb -m NAME -u agent -w DIR` with no command: `orb` then starts the login shell of `agent` from `/etc/passwd` in `DIR`, with a PTY when standard input is a terminal (OrbStack 2.2.5). `shellArgs` is exactly these six arguments. The user is the constant `AgentUser`; `DIR` is the only value of the caller besides the name, and `Shell` refuses it with `ErrMountPath` when it is not absolute or holds a colon or a comma (an absolute path never starts with `-`), before any command, also before `orb status`. The three streams go to `orb` as they are (`executeStreams`, no buffer), so that `orb` sees the terminal of the caller. `Shell` returns the exit status of `orb`, which passes the status of the shell through, 128 plus the signal number when a signal ended `orb`, and an error only when `orb` could not run. While `orb` runs, the process catches `SIGINT` and `SIGQUIT` (`holdingSignals`), so that a signal from the terminal ends `orb` and the caller returns its status; a caught signal, unlike an ignored one, reaches `orb` with its default action.
- Never run `orb delete` without exactly one machine name. `orb delete` takes several names and `-a/--all` deletes every machine (`orb delete --help`). `Delete` refuses a name without the prefix (`ErrForeignMachine`) or with white space (`ErrMachineName`) before any command, also before `orb status`, as `Start` and `Stop` do; `deleteArgs` is exactly `delete --force NAME`. `orbit destroy` is the first caller where a delete is the user's request.
- Every command of the client, `Shell` included, runs `orb` through `executeStreams`. A change to how `orb` is started (its environment, for example) goes there, so that it covers every command. `TestEveryCommandRunsOrbWithTheSameEnvironment` fails when one command gets another environment than the others, and `TestEveryCommandGetsOnlyAllowedVariables` checks the allowlist for every command, `Shell` included.
- The adapter imports no other package of this repository. Only `cmd/orbit` imports the adapter; `golangci-lint` (depguard) fails on any other import. Slices use `orbstacktest` in tests.
- `createArgs` passes `--forward-ssh-agent` only when the caller of `Create` asks for it (R08, D25); OrbStack fixes that setting at creation, and no `orb` command changes it later. `SSHAgentForwarded` reads `.config.forward_ssh_agent` from `orb list --format json` and fails on a missing machine, a missing field, or a value that is not a boolean: it never assumes a default. Add an operation only when a slice needs it, and add it to the fake in the same change.
- Every command of `orb` runs through `executeStreams`, which gives `orb` only the variables of `allowedVariables` from the environment of the process, matched by exact name, and removes every other one (owner decision on #76: an allowlist, not a list of forbidden names). The list is `HOME`, `PATH`, `TMPDIR`, `TERM`, `COLORTERM`, `LANG`, `LC_ALL`, `LC_COLLATE`, `LC_CTYPE`, `LC_MESSAGES`, `LC_MONETARY`, `LC_NUMERIC`, and `LC_TIME`. Why: `orb` copies some host variables into the command that it runs in the machine, as root and as the agent (the proxy variables, every `DOCKER_*`, `ELECTRON_RUN_AS_NODE`, terminal values, `LC_*`, `__CF*`, `COMMAND_MODE`), and `ORBENV` and `WSLENV` make it copy every host variable that they name (OrbStack 2.2.5). Without the allowlist a host credential could enter a sandbox without an opt-in (R08), and a variable that a later OrbStack starts to forward would pass. Why these names: with only `HOME` set, `orb` runs every command of the adapter, and without `HOME` it panics (`$HOME is not defined`): it finds OrbStack through `HOME` (#70). `PATH` and `TMPDIR` are what `orb`, a Go program, reads to find a program and a directory for temporary files; `orb` does not copy them into a machine. `orb` copies `TERM`, `COLORTERM`, and the `LC_` variables into the machine, where a terminal needs them (without `TERM` a command gets `TERM=dumb`). Do not run `orb` outside `executeStreams`. The integration check `checkShellGetsNoHostSecret` (`cmd/orbit`) shows that `ORBENV` and the secret it names do not reach an `orbit shell` session. Add a name to `allowedVariables` only when `orb` needs it, check whether `orb` copies it into a machine, and never add a prefix.
- The client never starts OrbStack. `orb` starts a stopped OrbStack by itself on any command that needs it (OrbStack 2.2.5, #62), so every command of the client first runs `orb status`, which only reports the state. Unless it prints `Running` and exits 0, the client runs no other command and fails: with `ErrNotRunning` and the advice to start OrbStack for `Stopped` or `Starting`, with an error for any other output. When `orb status` itself fails with `exec.ErrNotFound` (`orb` is not on `PATH`), the client fails with `ErrNotInstalled`, which also wraps `exec.ErrNotFound`, says that OrbStack is not installed or `orb` is not on `PATH`, and names `brew install --cask orbstack` and https://orbstack.dev (#143); it is not `ErrNotRunning`, and it runs no other command. No slice compares the error text. Do not add a path to `orb` that skips this check.
- `orb` finds OrbStack through `$HOME/.orbstack`. Under another `HOME` it prints `Stopped` while OrbStack runs (#70). Before `orb status` runs, the client reads `HOME`, the home directory of the account from the user database (`user.Current`), and whether `$HOME/.orbstack` is a directory. When `orb status` prints `Stopped` or `Starting` and `HOME` is not absolute, is not the same directory as the account home (symlinks resolved, then `os.SameFile`), or has no `.orbstack` directory, the client fails with `ErrHome`, which names `HOME` as the cause and advice for that cause, not with `ErrNotRunning`. It runs no other command. The client never runs `orb` with another `HOME` (owner decision on #70); `executeStreams` passes the `HOME` of the process unchanged, as one of the allowed variables.
- An error of a failed command wraps the error of `os/exec` and carries the standard error of `orb`, when `orb` printed anything.
- The fake applies the same prefix rule, the same white-space rule for `Start`, `Stop`, and `Delete`, and the same mount-path rule for `Create` and `Shell` as the adapter, with sentinel errors of its own. Keep the two in step. It keeps a state per machine that `Create`, `Start`, and `Stop` change; its `ActiveMounts` fails with `ErrNoMachine` for a machine that does not exist, and it, `RunAsRoot`, `RunAsAgent`, and `Shell` fail with `ErrStopped` for a machine that exists and is not running, so that a handler test catches an implicit start. `RunAsRoot`, `RunAsAgent`, and `Shell` of the fake accept a machine that was never added, because handler tests run a script in a machine that they did not add; the adapter fails there with `ErrMachineNotRunning`, which covers a machine that does not exist as well.

## Validation

- `go test ./internal/orbstack/...` needs no OrbStack.
- `go test -tags integration -count=1 -v ./internal/orbstack/...` needs a running OrbStack. It creates one machine named `orbit-it-<random>` and deletes it; it registers the deletion only after it saw that no machine has that name. Never touch a machine whose name does not start with `orbit-it-` from a test.
