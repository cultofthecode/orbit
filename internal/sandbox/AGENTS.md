# AGENTS.md — internal/sandbox

The sandbox module: the lifecycle of the sandbox of a project directory. Read the root `AGENTS.md` and `ARCHITECTURE.md` first. Every change here is `risk-high`.

## Layout

- `sandbox.go` — the root package: `NamePrefix`, `MachineName`, the errors that several slices report (`ErrNoSandbox`, `ErrUnexpectedState`, `ErrNotDirectory`, `ErrLinkedSandboxDir`, `ErrLinkedProjectDir`), `ExitStatus` (the non-zero status of a command that Orbit ran for the user; `cmd/orbit` exits with it and prints nothing), `ProjectDir`, `ProtectedDirs`, `ProtectedFiles`, `RelocatedDirs`, `RelocatedFiles`, `RelocatedSingleLinkFiles`, `ValidateProjectDir`, `ValidateNotNested`, `ValidateMounts`, `CheckSSHForwarding` (`ErrSSHForwardingMismatch`). Pure functions, no I/O.
- `initialize/` — the slice of `orbit init`. The package is not named `init`, because Go refuses to import a package under that name. It creates the machine, provisions it as root with the script that `Handler.ProvisionScript` returns (`provision.Script`, injected by `cmd/orbit`), and installs the agent of `--agent` as the agent user with the `Install` that `Handler.Agent` returns (a lookup in the registry of `internal/agent`, injected by `cmd/orbit`). `cmd/orbit` registers `NewCommand` as `orbit init`.
- `start/` — the slice of `orbit start`, and the only Orbit path that starts a machine. In order: (1) `hostcheck.ProjectDir` with freshly loaded facts, in every state, before any OrbStack call; (2) `State`: no machine is `ErrNoSandbox`, `running` is success without any other call, any state but `stopped` is `ErrUnexpectedState`; (3) `Mounts`: the configured mounts of the machine are exactly the project directory (`ValidateMounts`), and `hostcheck.Unnested` with `includeOwn` true; (4) `Start`; (5) `RunAsRoot` with `Handler.BootCheckScript` (`provision.BootCheckScript`, injected by `cmd/orbit`); (6) `ActiveMounts` through `ValidateMounts`; (7) `RunAsRoot` with `Handler.MarkerCheckScript` (`provision.MarkerCheckScript`). A failure of (4)–(6), a cancellation included, stops the machine again with a context that cancellation does not stop (`ErrBoundaryDown`); when that stop fails too, both errors are reported and the message names `orbit stop`. A failure of (7) leaves the machine running (`ErrNotProvisioned`) and names `orbit init`, because the boundary is up and `init` repairs only a running sandbox. `cmd/orbit` registers `NewCommand` as `orbit start`.
- `list/` — the slice of `orbit ls`. It reads only `Machines.List` (one snapshot of `orb list`), drops every name without `sandbox.NamePrefix` again (R07), and takes the project directory of each machine from `sandbox.StoredProjectDir`: the stored mount, exactly one mount `DIR:DIR`, `DIR` absolute and clean, `MachineName(DIR)` equal to the name; otherwise the row carries the reason and the command prints `?`. The directory is the stored configuration, not the kernel view and not a check of the host: no code may use the output of `ls` as a check. The handler never calls `State`, `Start`, `Stop`, `Create`, `Delete`, or any `-m` method; its test asserts that the fake records only `OpList`. An error of `List` returns no partial list. Every value that the command prints, in the table and in the reasons on stderr, goes through `printable`. `Machine` is the type of the slice; `cmd/orbit` converts `orbstack.Machine` to it, with a unit test for the converter, and the slice tests wrap `orbstacktest.Fake` the same way. `cmd/orbit` registers `NewCommand` as `orbit ls`.
- `stop/` — the slice of `orbit stop`. It resolves the current directory with `realpath.Resolve`, reads `State` of its machine, and runs `Stop` only for a `running` machine; it then reads `State` again and fails unless the machine is `stopped`. A `stopped` machine is success without `Stop`; no machine is `ErrNoSandbox`; any other state is `ErrUnexpectedState`, without `Stop`. It never names another machine. `cmd/orbit` registers `NewCommand` as `orbit stop`.
- `shell/` — the slice of `orbit shell`. In order: (1) `realpath.Resolve` of the current directory and `MachineName`, before any OrbStack call; the lookup is exact, so a subdirectory of a project has no sandbox; (2) `State`: no machine is `ErrNoSandbox` (names `orbit init` and the directory of `orbit init`), any state but `running` is `ErrNotRunning` (names `orbit start`), with no other call; (3) `Mounts` and `ActiveMounts`, both through `ValidateMounts` (`ErrMountMismatch`); (4) `RunAsRoot` with `Handler.ReadinessScript` (`provision.ReadinessScript`, injected by `cmd/orbit`); a failure is `ErrNotProvisioned`, which wraps the error of `RunAsRoot` and names `orbit init`; (5) `Shell` with the canonical directory and the streams of the command, unwrapped, so that `orb` sees the terminal. It returns the exit status of the shell; the command returns `ExitStatus` for a non-zero status. It never starts, provisions, repairs, or deletes a machine, writes nothing on the host or in the machine, and runs nothing in the shell (D19, R04). `cmd/orbit` registers `NewCommand` as `orbit shell`.
- `internal/hostcheck/` — private to the module: the host-side checks that run before a machine is created or started, moved unchanged from `initialize` so that every slice runs one implementation. `ProjectDir` loads the facts of a project directory (with the user lookup that the handler passes) and runs `ValidateProjectDir`; `Unnested` runs the nesting refusal and the symlink walk of the stored mount paths. The nesting comparison never counts the own machine; `includeOwn` adds its stored paths to the symlink walk only (`ErrLinkedProjectDir`): `init` passes `false`, because it may create the machine, `start` passes `true`, because those are the paths that OrbStack resolves at the start. Their errors that a caller names live in the root package (`ErrNotDirectory`, `ErrLinkedSandboxDir`, `ErrLinkedProjectDir`); `initialize` keeps the first two as aliases.
- `internal/realpath/` — private to the module: `Resolve` returns the canonical path of a directory, `ResolveWithOwner` that path and the owner from one open handle, and `ResolveNoFirmlink` its path on its own volume. Every slice resolves the project directory with `Resolve` or `ResolveWithOwner`.

## Invariants

- A decision about what a sandbox is or what enters it is a pure function in `sandbox.go`, with table tests that include hostile input. A handler loads the facts (`ProjectDir`) from the system, calls the function, and acts on the result. A fact that cannot be read is an error, never a default.
- `ValidateProjectDir` applies two independent rules, and both must accept the directory (R08, R09). Do not add an exception, and do not drop one rule because the other covers a case.
  - Paths: it refuses `/`; a home directory and every directory that contains one; a protected directory, every directory inside one, and every directory that contains one (`ErrProtectedDir`, `ErrProtectedAncestor`); and every directory that contains a protected file (`ErrProtectedFile`). It compares path components, not string prefixes.
  - The protected set (#28). A change to it changes the sandbox boundary, so it needs the owner's yes.

    | Path in every home | Kind | Holds |
    |---|---|---|
    | `.aws` | directory | AWS credentials and SSO cache |
    | `.claude` | directory | Claude Code configuration and state |
    | `.config/gh` | directory | GitHub CLI configuration and tokens |
    | `.gnupg` | directory | GnuPG private keys |
    | `.ssh` | directory | SSH keys and configuration |
    | `.claude.json` | file | Claude Code configuration and state |

    A protected file refuses the directory that holds it and every directory that contains that one, not the directories inside it: those do not contain the file. For `.claude.json` in the home directory itself, the home rules already refuse these.
  - Locations that the environment moves (#40). In the environment of the user who runs `orbit`, these variables move a protected location. `RelocatedDirs` and `RelocatedFiles` return the locations; the handler resolves them with the same rules as the paths in every home (symlinks and dangling targets followed, the nearest existing parent for a missing path, the walk of the symlinks in a protected directory) and adds them to `ProjectDir.Protected` and `ProjectDir.ProtectedFileDirs`. A variable can name a path through a project directory, so the handler also walks the path of each location with `linkSpellings` and adds every spelling of each directory that holds a symlink on it to `ProjectDir.ProtectedFileDirs` (`relocatedHopSpellings`): `GNUPGHOME=~/proj/cred` with `cred -> ~/vault/gnupg`, or `GNUPGHOME=~/proj/sub/gnupg` with `sub -> ~/vault`, refuses `~/proj`, because the agent could replace `cred` or `sub` and redirect the tool on the host. The paths in every home stay protected as well. A new variable needs the owner's yes.

    | Variable | Protected location | Kind |
    |---|---|---|
    | `CLAUDE_CONFIG_DIR` | the directory (with its `.claude.json`) | directory |
    | `GH_CONFIG_DIR` | the directory | directory |
    | `GNUPGHOME` | the directory | directory |
    | `XDG_CONFIG_HOME` | `$XDG_CONFIG_HOME/gh` | directory |
    | `AWS_CONFIG_FILE` | the file | file |
    | `AWS_SHARED_CREDENTIALS_FILE` | the file | file |

    An unset variable adds nothing. A set variable fails closed (`ErrRelocatedPath`, naming the variable; for an empty value the message says to unset it) when its value is empty (owner decision, 2026-11-11), relative (also `~/…` or `$HOME/…` that the shell did not expand), or has a `..` segment: a tool can read an empty or relative value against its own working directory, and a lexical clean of `..` after a symlink protects the wrong directory. A trailing separator, a repeated separator, and `.` are cleaned. A location that cannot be resolved (a symlink loop, a dangling target with `..` after a name, a directory variable that names a file) stops `init` and names the variable. Orbit reads only the values of the variables, never a file that they name (D08).
  - Ownership: it refuses a directory that the user does not own. This covers system directories such as `/System`, `/.vol`, `/.nofollow`, and `/.resolve`.
- The home directories are the one of `$HOME` and the one of the account database (`os/user`), each as its canonical path and as its path on its own volume. Both must exist. `$HOME` alone can name any directory, and on macOS the home directory `/Users/dev` is also `/System/Volumes/Data/Users/dev`, so `/System`, `/System/Volumes`, and `/System/Volumes/Data` contain it.
- A protected directory can be a symlink, and so can a directory on its path (`.config`). The handler resolves every path of `ProtectedDirs` and passes every spelling of its target in `ProjectDir.Protected`; for a path that does not exist, every spelling of its nearest existing parent joined with the rest of the path, so a missing `.config/gh` under a linked `.config` is protected where the GitHub CLI would create it. A protected file can be a symlink too: the handler follows every path of `ProtectedFiles` with `filepath.EvalSymlinks`, without opening the file (D08), and passes every spelling of the directory that holds the final target in `ProjectDir.ProtectedFileDirs`.
- A protected file can have hard links (#37, #69). A hard link is the same file under another name, in any directory of the volume, and Orbit cannot find it without a scan of every volume. So `ValidateProjectDir` refuses every project directory while a protected file has more hard links than were found in the protected locations (`FileLinks.Count > FileLinks.Found`, `ErrHardLinkedFile`, naming each such file once and asking the user to remove the other links), before the path rules and before any OrbStack call. The handler reads only metadata (`os.Lstat`, `os.ReadDir`) and never opens a file (D08). Only regular files count: a directory always has more than one link. Two rules fill `ProjectDir.ProtectedFileLinks`:
  - One link (owner decision, 2026-11-11): the files of `ProtectedFiles` (`~/.claude.json`) and of `RelocatedSingleLinkFiles` (`AWS_CONFIG_FILE`, `AWS_SHARED_CREDENTIALS_FILE`, `$CLAUDE_CONFIG_DIR/.claude.json`) have `Found` 1, so any second link refuses, also one inside a protected location. The refusal names the one-link path, so the user removes the other link. The handler follows each path with `filepath.EvalSymlinks`; a path that leads nowhere adds nothing, and a set variable that is empty, relative, or has `..` fails with `ErrRelocatedPath`.
  - Counted links (owner decision, 2026-11-11): every regular file in the walk of the protected directories (`ProtectedDirs` of every home and `RelocatedDirs`, with every directory that a symlink in one of them leads to, `linkedSpellings`) and every regular file where a chain of such a symlink ends. For each file (device and inode) the handler counts its distinct canonical paths in all these locations; a chain end counts under the canonical path of its directory and the name that the directory lists, so `/System/Volumes/Data/…` or another case names one path. Overlapping roots (`CLAUDE_CONFIG_DIR=~/.claude`, `XDG_CONFIG_HOME=~/.config`, `GNUPGHOME=~/.gnupg/sub`) count a path once. The walk does not list the directory that holds the end of a chain, so another link of that file in the same directory counts as outside and refuses `init`, although the path rules already keep that directory out of every mount: `~/.ssh/config -> ~/dotfiles/ssh/config` with a hard link `~/dotfiles/ssh/config.bak` refuses until the user removes `config.bak`. A double count would hide a link outside, so keep this. Links between protected locations pass: Claude Code shares snapshots in `~/.claude/file-history`, and GnuPG makes a lock pair in `~/.gnupg/public-keys.d`.
  - The walk fails closed: a directory that it cannot read, an `Lstat` error other than "not exist", an unknown `Sys()` type, or a chain end that is one of several links in one directory under a name that the directory does not list stops `init`. Files outside the protected locations, and a link that the user makes on the host after `init`, are out of scope (#69). A hard link that a host tool makes or removes during the walk (Claude Code in `~/.claude/file-history`) can refuse `init` once; run it again.
- A protected path can lead nowhere yet (#27): `~/.ssh -> ~/dotfiles/ssh` before that directory exists, or `~/.config -> ~/proj/config` while `.config/gh` does not exist. The tool creates its credentials at the target, so the handler follows a dangling symlink on the way (`targetSpellings`, at most 32 hops) and protects where the target would be created: as a directory for `ProtectedDirs`, and its parent directory for `ProtectedFiles`. A dangling target that has `..` after another name stops `init` (`errUnresolvableLink`): when that name is a symlink, the kernel applies `..` to its target, so a lexical join would protect the wrong directory.
- A protected directory can hold symlinks, as a per-file dotfiles layout makes it (#27): `~/.ssh/id_ed25519 -> ~/dotfiles/ssh/id_ed25519`. The handler walks every protected directory that exists, and every directory that a symlink in one of them leads to, without following a symlink to walk it (`linkedSpellings`). It resolves the chain of each symlink one name at a time, as the kernel does (`linkSpellings`, at most 32 hops). Every directory that holds a symlink on the chain goes to `ProtectedFileDirs`: the first target, every later hop, and a linked directory on the way (`~/.ssh/config -> ~/proj/link/config` with `~/proj/link -> ~/vault` protects `~/proj` and `~/vault`), because the agent could replace a hop in a mounted directory. Where the chain ends, a directory goes to `Protected`; a file adds the directory that holds it to `ProtectedFileDirs`; a target that does not exist adds where it would be created to `Protected`, because the handler cannot know whether it will be a file or a directory. It reads only metadata and never opens a file (D08).
- A protected path, or a symlink in a protected directory, that exists and cannot be resolved stops `init`, and so does a directory in the walk that cannot be read. A hop in the middle of the chain of a protected path itself (`ProtectedDirs`, `ProtectedFiles`) is not protected yet (#36); the hops of a symlink inside a protected directory are, and so are the hops on the path of a location that the environment moves.
- Pass only canonical paths to `ValidateProjectDir` and `MachineName`. On macOS `filepath.EvalSymlinks` is not enough: `/users/DEV` and `/System/Volumes/Data/Users/dev` both name the home directory. Resolve every path with `realpath.Resolve` (`F_GETPATH` on macOS), in every slice, so that all slices compute the same machine name for a directory. On macOS the tests of the other spellings fail when the file system does not accept a spelling; they never skip there.
- Read the canonical path and the owner of the project directory from one open handle (`realpath.ResolveWithOwner`: `open(O_SEARCH)`, `fstat`, `F_GETPATH`). Two lookups of the path can name two directories.
- `orb` resolves the mount path again, at every start of the machine, and follows a symlink in it. So the check of the path alone cannot hold, and `init` has two more layers (#29). Keep both.
  - It refuses a project directory that is, lies inside, or contains a directory that another machine mounts (`ValidateNotNested`: `ErrNestedProjectDir` when it is or lies inside one, `ErrContainsProjectDir` when it contains one). Both directions matter: inside a mounted directory, the agent of that machine controls the path of the new mount; above one, the new agent controls the path of the older mount, and OrbStack follows a swapped path at the next start of the older machine. It compares each mounted directory as OrbStack stores it, also when that directory no longer exists, because OrbStack resolves the stored path again at the next start. It refuses a stored path that is not absolute and clean (`ErrPathNotClean`) before it reads the file system. Then it compares every spelling that each stored path resolves to; for a path that does not exist, every spelling of its nearest existing parent joined with the rest of the path. Last, it walks the components of each stored path with `os.Lstat` and refuses `init` when a component that exists is a symlink (`ErrLinkedSandboxDir`, naming that machine), for every project directory, until the user fixes the path or deletes that machine. Orbit stores canonical paths, so such a symlink means that the host layout changed after that machine was created; the spellings miss a symlink that dangles or whose hop lies in the new directory, and OrbStack follows it at the next start. A component that does not exist ends the walk; every other error stops `init`. It refuses before it creates a machine. **This refusal protects a sandbox only against the folder layout at the moment `init` runs.** A host-side move after `init` (for example `mv ~/proj ~/work/proj && ln -s work/proj ~/proj`) points the stored path of an existing sandbox into another sandbox without any `init`, and no check at `init` time can see it. A slice that starts a machine (`start`) is therefore required, not optional, to re-run this refusal before every start.
  - After it creates a machine, and for a machine that already exists, it checks that the configuration and the kernel of the machine (`/proc/self/mountinfo`) both mount exactly the project directory at its own path (`ValidateMounts`, `ErrMountMismatch`). It deletes a machine that it created and that fails the check, and never one that existed before. It never provisions a machine that fails the check. This check is defense in depth, not proof of the mounted directory: the root field of `mountinfo` names the path of the mounted dentry, not the identity of the directory. It shows a symlink that was in place before the machine mounted the path. It does not show a path that was removed and recreated as a symlink between two starts: on OrbStack 2.2.5, after a restart, the kernel still reports the stored path while the machine serves the target of the symlink. A guest cache can also keep the original directory, so the result depends on the cache state. A slice that starts a machine (`start`) must not rely on this check alone; it is required to re-run the nesting refusal as well.
- The machine of a directory is found by its name: `orbit-<slug>-<hash>`, where the slug has at most 30 characters and the hash is the first 16 hex characters of the SHA-256 of the canonical path. A change to `MachineName` orphans every existing sandbox.
- Only `start` starts a machine, and only after the host-side checks of step (1) and (3) passed. Every `-m` command (`ActiveMounts`, `RunAsRoot`, `RunAsAgent`, `Shell`) starts a stopped machine, so a slice other than `start` reads `State` first and runs them only on a `running` machine (`shell` and `init` do: `init` on an existing machine that is not `running` fails with `initialize.ErrNotRunning` and names `orbit start`, before any command in it, #75; the client also refuses with `orbstack.ErrMachineNotRunning`); `start` runs them only after its own `Start`. `orbstacktest` refuses them for a machine that is not running, so a handler test catches an implicit start.
- A slice declares the narrow interface that it needs from OrbStack and is tested against `internal/orbstack/orbstacktest`. No package here imports `internal/orbstack`; `golangci-lint` (depguard) fails on it.
- A slice does not import another slice, and it does not import another module: `cmd/orbit` injects functions such as `provision.Script`.
- `init` resolves the agent, validates the directory, and builds the provisioning script, which validates the agent domains, before its first OrbStack call. An unknown agent and a hostile domain create no machine.
- `init` forwards the host SSH agent unless `--no-ssh-forwarding` is passed (R08, D25). OrbStack fixes the setting at creation, so after it finds or creates the machine, and before the mount check, whose `ActiveMounts` is the first command in the machine, `init` reads the setting from `orb list` (`SSHAgentForwarded`) and compares it with the request through `CheckSSHForwarding`. On an existing machine a mismatch is `ErrSSHForwardingMismatch`, and `init` runs nothing in it: no start, no provisioning, no delete (Q1); the message names `init --no-ssh-forwarding` and deleting the sandbox to recreate it. On a machine that this call created, a mismatch deletes it. A sandbox from before E01-S04 has forwarding off, so a plain `init` refuses it and `init --no-ssh-forwarding` keeps it.
- `init` provisions every time it runs, also on an existing machine, and only after the forwarding check and the mount check passed. Then, when `--agent` is set, it runs the `Install` of the agent through `RunAsAgent`, wrapped in one braced group with `set -euo pipefail` and the proxy settings of `/etc/environment`: a truncated script fails to parse, and a failed download fails the install. No slice compares an agent name. Each `init` rebuilds the allowlist from its own `--agent`; Orbit stores no record of the installed agent.
- When the forwarding check, the mount check, provisioning, or the install fails on a machine that the same call created, `init` deletes that machine (with a context that cancellation does not stop). It never deletes a machine that existed before the call.

## Validation

`go test ./internal/sandbox/...` needs no OrbStack.
