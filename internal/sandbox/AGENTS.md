# AGENTS.md — internal/sandbox

The sandbox module: the lifecycle of the sandbox of a project directory. Read the root `AGENTS.md` and `ARCHITECTURE.md` first. Every change here is `risk-high`.

## Layout

- `sandbox.go` — the root package: `NamePrefix`, `MachineName`, `ProjectDir`, `ProtectedDirs`, `ProtectedFiles`, `ValidateProjectDir`, `ValidateNotNested`, `ValidateMounts`. Pure functions, no I/O.
- `initialize/` — the slice of `orbit init`. The package is not named `init`, because Go refuses to import a package under that name. It creates the machine and provisions it as root with the script that `Handler.ProvisionScript` returns (`provision.Script`, injected by `cmd/orbit`). `NewCommand` is not registered in `cmd/orbit` until the agent is installed as well (story E01-S01).
- `internal/realpath/` — private to the module: `Resolve` returns the canonical path of a directory, `ResolveWithOwner` that path and the owner from one open handle, and `ResolveNoFirmlink` its path on its own volume. Every slice resolves the project directory with `Resolve` or `ResolveWithOwner`.

## Invariants

- A decision about what a sandbox is or what enters it is a pure function in `sandbox.go`, with table tests that include hostile input. A handler loads the facts (`ProjectDir`) from the system, calls the function, and acts on the result. A fact that cannot be read is an error, never a default.
- `ValidateProjectDir` applies two independent rules, and both must accept the directory (R08, R09). Do not add an exception, and do not drop one rule because the other covers a case.
  - Paths: it refuses `/`; a home directory and every directory that contains one; a protected directory, every directory inside one, and every directory that contains one (`ErrProtectedDir`, `ErrProtectedAncestor`); and every directory that contains a protected file (`ErrProtectedFile`). It compares path components, not string prefixes.
  - The protected set (#28). A change to it changes the sandbox boundary, so it needs the owner's yes.

    | Path in every home | Kind | Holds |
    |---|---|---|
    | `.aws` | directory | AWS credentials and SSO cache |
    | `.claude` | directory | Claude Code configuration and state |
    | `.config/gh` | directory | GitHub CLI configuration and tokens |
    | `.gnupg` | directory | GnuPG private keys |
    | `.ssh` | directory | SSH keys and configuration |
    | `.claude.json` | file | Claude Code configuration and state |

    A protected file refuses the directory that holds it and every directory that contains that one, not the directories inside it: those do not contain the file. For `.claude.json` in the home directory itself, the home rules already refuse these.
  - Ownership: it refuses a directory that the user does not own. This covers system directories such as `/System`, `/.vol`, `/.nofollow`, and `/.resolve`.
- The home directories are the one of `$HOME` and the one of the account database (`os/user`), each as its canonical path and as its path on its own volume. Both must exist. `$HOME` alone can name any directory, and on macOS the home directory `/Users/dev` is also `/System/Volumes/Data/Users/dev`, so `/System`, `/System/Volumes`, and `/System/Volumes/Data` contain it.
- A protected directory can be a symlink, and so can a directory on its path (`.config`). The handler resolves every path of `ProtectedDirs` and passes every spelling of its target in `ProjectDir.Protected`; for a path that does not exist, every spelling of its nearest existing parent joined with the rest of the path, so a missing `.config/gh` under a linked `.config` is protected where the GitHub CLI would create it. A protected file can be a symlink too: the handler follows every path of `ProtectedFiles` that exists with `filepath.EvalSymlinks`, without opening the file (D08), and passes every spelling of the directory that holds the final target in `ProjectDir.ProtectedFileDirs`. A protected path that exists and cannot be resolved stops `init`; a broken symlink protects nothing (known gap, #27).
- Pass only canonical paths to `ValidateProjectDir` and `MachineName`. On macOS `filepath.EvalSymlinks` is not enough: `/users/DEV` and `/System/Volumes/Data/Users/dev` both name the home directory. Resolve every path with `realpath.Resolve` (`F_GETPATH` on macOS), in every slice, so that all slices compute the same machine name for a directory. On macOS the tests of the other spellings fail when the file system does not accept a spelling; they never skip there.
- Read the canonical path and the owner of the project directory from one open handle (`realpath.ResolveWithOwner`: `open(O_SEARCH)`, `fstat`, `F_GETPATH`). Two lookups of the path can name two directories.
- `orb` resolves the mount path again, at every start of the machine, and follows a symlink in it. So the check of the path alone cannot hold, and `init` has two more layers (#29). Keep both.
  - It refuses a project directory that is, lies inside, or contains a directory that another machine mounts (`ValidateNotNested`: `ErrNestedProjectDir` when it is or lies inside one, `ErrContainsProjectDir` when it contains one). Both directions matter: inside a mounted directory, the agent of that machine controls the path of the new mount; above one, the new agent controls the path of the older mount, and OrbStack follows a swapped path at the next start of the older machine. It compares each mounted directory as OrbStack stores it, also when that directory no longer exists, because OrbStack resolves the stored path again at the next start. It refuses a stored path that is not absolute and clean (`ErrPathNotClean`) before it reads the file system. Then it compares every spelling that each stored path resolves to; for a path that does not exist, every spelling of its nearest existing parent joined with the rest of the path. Last, it walks the components of each stored path with `os.Lstat` and refuses `init` when a component that exists is a symlink (`ErrLinkedSandboxDir`, naming that machine), for every project directory, until the user fixes the path or deletes that machine. Orbit stores canonical paths, so such a symlink means that the host layout changed after that machine was created; the spellings miss a symlink that dangles or whose hop lies in the new directory, and OrbStack follows it at the next start. A component that does not exist ends the walk; every other error stops `init`. It refuses before it creates a machine. **This refusal protects a sandbox only against the folder layout at the moment `init` runs.** A host-side move after `init` (for example `mv ~/proj ~/work/proj && ln -s work/proj ~/proj`) points the stored path of an existing sandbox into another sandbox without any `init`, and no check at `init` time can see it. A slice that starts a machine (`run`) is therefore required, not optional, to re-run this refusal before every start.
  - After it creates a machine, and for a machine that already exists, it checks that the configuration and the kernel of the machine (`/proc/self/mountinfo`) both mount exactly the project directory at its own path (`ValidateMounts`, `ErrMountMismatch`). It deletes a machine that it created and that fails the check, and never one that existed before. It never provisions a machine that fails the check. This check is defense in depth, not proof of the mounted directory: the root field of `mountinfo` names the path of the mounted dentry, not the identity of the directory. It shows a symlink that was in place before the machine mounted the path. It does not show a path that was removed and recreated as a symlink between two starts: on OrbStack 2.2.5, after a restart, the kernel still reports the stored path while the machine serves the target of the symlink. A guest cache can also keep the original directory, so the result depends on the cache state. A later slice that starts a machine (`run`) must not rely on this check alone; it is required to re-run the nesting refusal as well.
- The machine of a directory is found by its name: `orbit-<slug>-<hash>`, where the slug has at most 30 characters and the hash is the first 16 hex characters of the SHA-256 of the canonical path. A change to `MachineName` orphans every existing sandbox.
- A slice declares the narrow interface that it needs from OrbStack and is tested against `internal/orbstack/orbstacktest`. No package here imports `internal/orbstack`; `golangci-lint` (depguard) fails on it.
- A slice does not import another slice, and it does not import another module: `cmd/orbit` injects functions such as `provision.Script`.
- `init` provisions every time it runs, also on an existing machine, and only after the mount check passed. When the mount check or provisioning fails on a machine that the same call created, it deletes that machine (with a context that cancellation does not stop). It never deletes a machine that existed before the call.

## Validation

`go test ./internal/sandbox/...` needs no OrbStack.
